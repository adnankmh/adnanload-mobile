# سياسة إصدار APK/AAB

**لا تنشر حزم CI مباشرة**: قد تستعمل توقيعًا تجريبيًا إلى أن يُضبط توقيع release الخاص بمؤسسة التوزيع. لا تتضمن ZIP أي كلمة مرور أو keystore، ولا يجوز حفظهما في GitHub Repository.

**الأوامر:**
```bash
flutter create --platforms=android --org com.adnanload --project-name adnanload_mobile .
python3 tools/configure_android.py
flutter pub get
flutter analyze
flutter test
flutter build apk --release --split-per-abi
flutter build appbundle --release
```

**للتوزيع الحقيقي:** اضبط إعدادات التوقيع في Gradle باستخدام KeyStore release محفوظ خارج المشروع، واستخدم سرًا عبر مدير أسرار المؤسسة. اختبر التثبيت والترقية والتراجع وعمليات المسح والتكامل على هاتف فعلي، وراجع أحجام حزم arm64 قبل النشر. لا يوجد أي توقيع إنتاجي ضمن هذا المصدر.

**سياسة الأمن:** بيانات الجلسات والروابط الخاصة ملك المستخدم، لا تُرفع سجلات الأعطال تلقائيًا، ولا يُخزّن فيها محتوى الروابط أو أسماء الملفات. فحص SHA-256 اختياري عندما يقدّم المستخدم بصمة موثوقة، وليس بديلًا عن مسح أمني للملفات التنفيذية. يظل تنزيل المحتوى مقيدًا بحقوقه وسياسات المواقع، دون تجاوز DRM أو أنظمة الدفع.

**Android:** `RUN_USER_INITIATED_JOBS` موجود لخدمة UIDT على Android 14+، لكن قد يطبق النظام مددًا وقيودًا تعتمد على الجهاز ومستوى API وإذن الإشعارات. افحص الخدمة والإشعارات فعليًا قبل التسويق.
